마카오 가족여행 전용 웹사이트 제작 프롬프트
당신은 시니어 프로덕트 디자이너, 풀스택 개발자, 한국인 가족여행 전문 콘텐츠 에디터 역할을 수행한다.
아래 요구사항을 바탕으로 2026년 10월 12일 월요일부터 10월 15일 목요일까지의 마카오 가족여행을 위한 한국어 웹사이트를 설계하고 구현하라.
단순한 여행지 소개 페이지나 디자인 시안으로 끝내지 말고, 가족 5명이 휴대전화와 태블릿으로 실제 여행 중 사용하는 완성도 높은 여행 안내 서비스를 만들어라.
핵심은 다음과 같다.
- 선택한 여행자와 소속 팀에 맞는 여행 일정
- 마카오 현지 시간에 따라 지금 할 일과 다음 일정을 알려주는 안내
- 현재 위치와 목적지, 이동 방법을 연결하는 지도
- 부모님의 체력과 휴식을 고려한 현실적인 동선
- 출처가 확인된 관광·음식·공연·교통 정보
- 사진과 한국어 설명이 충분한 상세 콘텐츠
- 서버에 저장되는 프로필 이미지
- Render에 배포할 수 있는 실행 및 저장 구조
1. 작업 원칙과 정보의 신뢰성
1.1 실제 구현을 완료할 것
기획 설명이나 정적인 목업만 제출하지 않는다.
페이지 이동, 프로필 선택, 이미지 교체, 날짜 전환, 팀별 일정 분기, 지도 표시, 외부 길찾기, 상세정보 열람 등 주요 기능을 실제로 구현한다.
동작하지 않는 버튼, 임의의 후기, 의미 없는 샘플 콘텐츠로 완성된 것처럼 보이게 하지 않는다.
1.2 제공된 예시는 검증 대상이다
원문에 등장하는 셔틀 운행 간격, 버스 번호, 요금, 탑승 장소, 식당 운영시간, 공연시간, 무료 케이블카 이용 조건은 확정된 사실이 아니다.
공식 웹사이트와 신뢰할 수 있는 최신 자료를 조사해 확인한다. 특히 다음 항목은 우선 검증한다.
- 베네시안 호텔 셔틀의 목적지, 첫차·막차, 탑승장, 이용 조건
- 세나도 광장으로 가는 버스 노선과 승하차 정류장
- 오픈탑 나이트 투어의 실제 상품, 출발 시각, 집결지
- 윈팰리스 분수쇼 및 케이블카 운영 여부와 이용 조건
- 원문에 적힌 ‘시티오브시티 호텔 돈키호테’의 정확한 시설명·매장 위치·영업 여부
- 각 식당의 운영시간, 브레이크타임, 가격, 예약 방법
- 공항 이동시간과 항공사 권장 수속시간
공식 정보가 없거나 여행일 기준 운영이 아직 확정되지 않았다면 **‘확인 필요’ 또는 ‘추후 공지’**로 표시한다.
검색 결과의 짧은 요약만 보고 정보를 확정하지 말고, 가능한 경우 원문 페이지를 확인한다.
1.3 출처를 콘텐츠와 연결할 것
주요 장소·교통·공연·식당 정보에는 다음을 저장하고 표시한다.
- 출처명
- 출처 URL
- 확인일
- 정보 적용일 또는 운영 기간이 있는 경우 해당 기간
- 확인 상태: 확인됨 / 예상 / 확인 필요
현재 운영정보와 2026년 10월 여행일의 확정정보를 구분한다. 지금 확인한 운영시간을 미래 여행일에도 보장되는 것처럼 표현하지 않는다.
1.4 평점과 후기를 만들지 말 것
실제 외부 평점에는 플랫폼 이름, 점수 기준, 리뷰 수, 확인일을 함께 표시한다.
접근할 수 없는 평점이나 후기를 임의로 생성하지 않는다. 실제 이용자가 작성한 것처럼 가상의 후기를 만들지 않는다.
별도의 자체 추천 점수가 필요하다면 **‘우리 가족 적합도’**로 명확히 구분하고, 다음 평가 근거를 공개한다.
- 부모님 이동 편의
- 음식 선택 폭
- 서비스 관련 확인 가능한 평가
- 대기 부담
- 가격
- 여행 동선과의 거리
외부 평점과 자체 추천 점수가 혼동되지 않도록 디자인한다.

원문 일부의 날짜·요일 표기는 서로 맞지 않는다. 구현에는 아래 조합을 적용한다.
- 10월 12일: 월요일
- 10월 13일: 화요일
- 10월 14일: 수요일
- 10월 15일: 목요일

3. 사용자 선택과 프로필
3.1 첫 접속 화면
메인 일정에 들어가기 전에 여행자 선택 화면을 제공한다.
- 여행자 5명의 프로필 이미지와 이름을 모두 표시한다.
- 이름과 함께 A팀 또는 B팀 배지를 표시한다.
- 기본 이미지는 각각 다른 귀여운 동물 일러스트로 구성한다.
- 어린이용 서비스처럼 보이지 않도록 차분하고 세련되게 디자인한다.
- 큰 터치 영역과 읽기 쉬운 이름을 사용한다.
- 선택 후 해당 여행자의 팀에 맞는 메인 일정으로 진입한다.
선택한 여행자 ID는 기기에 저장하여 재방문 시 복원한다. 프로필 메뉴에서 다른 여행자로 전환할 수 있게 한다.
3.2 프로필 페이지
다음 정보를 표시한다.
- 프로필 이미지
- 이름
- 고정 소속 팀
- 숙박 기간
- 출국 및 귀국 일정
프로필 사진은 사용자가 업로드하여 교체할 수 있다.
필수 동작:
- 사진 선택
- 업로드 전 미리보기
- 원형 또는 정사각형 크롭
- 저장 중 상태 표시
- 성공·실패 안내
- 기본 동물 이미지로 복원
사진은 서버에 저장하고, 새로고침하거나 다른 기기에서 같은 여행자를 선택해도 저장된 사진을 볼 수 있게 한다.
프로필 선택 자체는 본인 인증이 아니라는 점을 고려한다. 가족용 접근코드 등 가벼운 공통 접근 보호를 적용하고, 이름·팀 등 고정 데이터는 클라이언트 요청으로 변경할 수 없게 한다.
공유 URL이나 프런트엔드 소스에 접근코드·비밀값을 넣지 않는다.
4. 화면 구성과 정보 구조
휴대전화에서 가장 많이 쓰는 기능을 기준으로 다음 화면을 구성한다.
1. 여행자 선택
2. 오늘의 여행
3. 날짜별 전체 일정
4. 지도와 현재 위치
5. 장소·식당·공연 상세
6. 여행 준비 및 공항 안내
7. 프로필
모바일 하단 내비게이션은 다음을 기본으로 한다.
- 오늘
- 전체 일정
- 지도
- 여행 정보
- 내 프로필
현재 보고 있는 날짜, 여행자, 소속 팀이 항상 쉽게 파악되어야 한다.
4.1 오늘의 여행 화면
상단에 다음을 표시한다.
- 현재 여행자와 팀
- 마카오 현지 날짜·요일·시간
- 한국 시간 보조 표시
- 여행 D-day 또는 여행 몇 일차
- 다음 일정과 남은 시간
본문에는 다음 순서로 정보를 배치한다.
1. 현재 예정된 일정
2. 다음 일정
3. 지금 출발해야 하는 경우 출발 안내
4. 오늘의 핵심 일정 요약
5. 식사·공연·교통 관련 주요 안내
시간이 지났다는 이유만으로 사용자가 실제 방문을 완료했다고 표시하지 않는다. **‘예정 시간 기준’**이라는 맥락이 드러나게 한다.
여행 전에는 준비 안내와 날짜별 미리보기를, 여행 후에는 완료된 여행 일정 열람 화면을 제공한다.
4.2 날짜별 일정
날짜 탭은 다음 네 개다.
- 10/12 월
- 10/13 화
- 10/14 수
- 10/15 목
일정 카드는 다음을 포함한다.
- 시작·종료 예정 시간
- 장소명과 한 줄 설명
- 적용 팀
- 대표 이미지
- 이동수단과 이동시간
- 예상 체류시간
- 예상 비용과 인원 기준
- 도보 부담 및 휴식 여부
- 예약 여부
- 상세보기와 길찾기
공통 일정은 함께 보이게 하고, 팀별 일정은 색상과 텍스트 배지로 구분한다.
B팀 사용자의 10월 15일 기본 화면에는 귀국 완료 상태를 보여준다. A팀의 남은 일정은 별도 동작으로 열람할 수 있다.
5. 날짜별 여행 콘텐츠
모든 시간표는 이동·대기·휴식까지 포함해 현실적으로 작성한다. 확정 예약이 없는 추천 일정은 ‘제안 일정’으로 구분한다.
부모님의 나이와 보행 능력은 구체적으로 주어지지 않았으므로 임의의 건강 상태를 가정하지 않는다. 대신 오래 걷는 구간, 계단, 더위 노출, 앉아서 쉬기 좋은 장소를 안내한다.
5.1 1일차 — 10월 12일 월요일
기본 흐름:
마카오 도착 → 입국·수하물 수령 → 호텔 이동 → 짐 보관 및 가벼운 호텔 구경 → 15:00 체크인 → 객실 휴식 → 늦은 점심 겸 이른 저녁 → 오픈탑 버스 투어.
새벽 출국에 따른 피로를 고려해 첫날 관광을 과밀하게 구성하지 않는다.
식사 추천
베네시안 내부 또는 도보로 접근하기 쉬운 주변 식당을 최소 5곳 제시한다. 뷔페도 후보에 포함하되 실제 영업과 식사 제공 시간대를 확인한다.
각 식당에 다음을 포함한다.
- 한국어 이름과 현지 표기
- 대표 음식과 한국어 메뉴 설명
- 실제 음식·매장 이미지
- 호텔에서의 이동 방법과 도보 부담
- 늦은 점심 또는 이른 저녁 가능 여부
- 1인 예상 비용과 5인 총액
- 세금·봉사료 포함 여부 또는 확인 필요 표시
- 결제수단
- 예약 방법
- 부모님과 방문할 때의 장점과 주의점
- 실제 평점·후기 요약 및 출처
- 우리 가족에게 추천하는 이유
한국인 후기와 서비스 관련 평가를 확인하되, 소수의 후기만으로 ‘한국인이 모두 좋아하는 맛집’처럼 단정하지 않는다.
오픈탑 나이트 투어
사용자의 목표는 20:30 출발, 20:20 이전 집결지 도착이다.
먼저 실제 상품과 출발 시각·집결지를 검증한다. 해당 시각의 상품을 확인하지 못하면 확정 예약처럼 표시하지 말고, 확인 필요 상태와 대체 상품을 제시한다.
집결지가 외항 페리 터미널로 확인되는 경우, 베네시안에서 이동하는 다음 세 가지 방법을 비교한다.
1. 호텔 무료 셔틀
2. 시내버스
3. 택시
각 방법에 다음 정보를 작성한다.
- 호텔 내부에서 탑승장까지 가는 방법
- 정확한 탑승장·행선지·정류장 표기
- 대기시간과 이동시간 범위
- 하차 후 집결지까지 걷는 시간

6. 지도와 현재 위치
브라우저 Geolocation API로 사용자 본인의 현재 기기 위치를 확인하는 기능을 구현한다.
위치 권한은 첫 화면에서 자동 요청하지 않고, 사용자가 ‘내 위치 확인’을 누를 때 요청한다.
필수 기능:
- 내 위치 마커
- 날짜별 장소 마커
- 팀별 장소 필터
- 장소 선택 시 요약 카드
- 현재 위치에서 목적지로 길찾기
- 위치 정확도와 마지막 갱신 시각
- 위치 사용 중지
- 권한 거부·위치 확인 실패 시 대체 안내
위치 확인이 실패하면 호텔이나 사용자가 선택한 장소를 출발지로 사용할 수 있게 한다.
현재 위치는 기본적으로 서버에 수집하거나 저장하지 않는다. 가족의 실시간 위치 공유 기능으로 확대하지 않는다.
지도는 API 키, 비용, 운영 정책을 비교해 Google Maps 또는 적절한 OpenStreetMap 기반 구성을 선택한다. 지도 라이브러리와 지도 타일 제공 서비스는 구분하고, 무료 라이브러리를 쓴다는 이유로 타일 사용도 무제한 무료라고 가정하지 않는다.
지도 출처 표기를 유지한다.
실제 도로 경로를 제공할 수 없다면 장소를 연결한 선을 **‘방문 순서’**로 표시하고 길찾기 경로처럼 보이게 하지 않는다. 도보·차량 경로와 소요시간은 경로 서비스 또는 외부 지도 길찾기로 제공한다.
GPS 없이도 전체 일정과 장소 정보를 사용할 수 있어야 한다.

사용자 화면은 한국어를 기본으로 하되, 택시 기사나 현장 직원에게 보여줄 수 있도록 현지 주소와 장소명을 크게 표시하는 기능을 제공한다.
이미지와 영상
실제 장소를 설명하는 데 적합하고 이용 조건이 확인되는 이미지를 사용한다.
AI 생성 이미지를 실제 식당·객실·메뉴 사진처럼 사용하지 않는다. 생성 이미지가 필요하면 표지용 일러스트 등으로 역할을 구분한다.
이미지 로딩 실패 시 레이아웃이 무너지지 않도록 한다.
관련 한국어 유튜브 영상이 있다면 다음을 표시한다.
- 영상 제목
- 채널명
- 업로드일
- 관련 장소
- 참고할 내용
- 재생 또는 유튜브에서 보기
가짜 영상 링크를 만들지 않는다. 임베드가 허용되지 않으면 외부 링크로 제공한다. 영상 속 과거 정보를 현재 운영정보로 취급하지 않는다.
8. 디자인과 접근성
디자인 콘셉트는 **‘마카오의 낮과 밤을 담은 세련된 가족여행 가이드’**다.
마카오의 포르투갈식 타일, 코타이 호텔의 야경, 따뜻한 크림색, 짙은 청록색, 절제된 골드 포인트를 시각적 영감으로 활용한다.
화려한 배경보다 일정·시간·이동 정보의 가독성을 우선한다.
모바일·태블릿
- 모바일은 한 손 조작이 쉬운 구조로 설계한다.
- 주요 버튼은 최소 44×44 CSS px 이상의 터치 영역을 확보한다.
- 본문 글자는 16px 이상을 기본으로 한다.
- 날짜 탭과 하단 내비게이션이 콘텐츠를 가리지 않게 한다.
- 태블릿 가로 화면은 일정과 지도를 나란히 볼 수 있게 한다.
- 장소 상세는 모바일에서는 시트 또는 독립 화면, 태블릿에서는 넓은 패널 구조를 검토한다.
- 사진을 많이 사용하되 한 화면에 정보를 과도하게 밀어 넣지 않는다.
접근성
- 충분한 명도 대비
- 이미지 대체 텍스트
- 키보드 탐색 및 포커스 표시
- 색상 이외의 팀 구분
- 모션 감소 설정 대응
- 긴 이름과 큰 글자에서도 깨지지 않는 레이아웃
- 오류 상황에서 다음 행동을 알려주는 문구
카지노 입장이나 카지노 내부 통과를 가족 이동의 기본 전제로 삼지 않는다. 실제로 해당 구간이 필요한 경우 이용 조건과 우회 경로를 확인한다.
9. 시간 처리와 일정 상태
날짜·시간 계산을 브라우저의 로컬 시간대에 의존하지 않게 한다.
- 여행지 일정: Asia/Macau
- 한국 공항 일정: Asia/Seoul
- 일정 시작·종료는 날짜와 시간대를 포함하여 저장
- 표시와 비교는 명시적인 시간대 기준으로 처리
다음 상태를 구현한다.
- 여행 전
- 오늘 예정
- 현재 예정 시간
- 다음 일정
- 예정 시간 경과
- 해당 팀 여행 종료
‘현재 예정 시간’과 실제 위치·방문 완료는 다른 개념으로 처리한다.
여행일 이전에도 동작을 확인할 수 있도록 개발 또는 미리보기 모드에 날짜·시간 시뮬레이션을 제공한다. 시뮬레이션 중에는 실제 현재 시간이 아니라는 표시를 명확히 한다.
10. 데이터와 서버 구조
별도 데이터베이스는 사용하지 않는다.
권장 기본 구성은 TypeScript 기반 프런트엔드 + Node.js 서버 + 구조화된 JSON 콘텐츠 + 파일 기반 프로필 저장이다. 기존 프로젝트가 있다면 그 구조를 먼저 확인하고 불필요한 재구축을 피한다.

- 장소

- 출처

여행 콘텐츠는 버전 관리되는 정적 JSON 등으로 관리하고, 변경 가능한 프로필과 업로드 이미지는 영속 저장 경로에 둔다.

- teamIds
- title
- category

비용에는 통화, 인원수, 1인/총액 구분, 포함·불포함 항목을 저장한다.
마카오 파타카, 홍콩달러, 원화 환산을 혼동하지 않는다. 원화 환산에는 환율 기준일을 표시하고, 실시간 환율 연동이 없으면 참고 환산임을 명시한다.
업로드와 저장
- 허용 확장자와 실제 이미지 형식을 모두 검사
- 파일 크기 및 해상도 제한
- 서버에서 이미지 재인코딩과 크기 최적화
- EXIF 위치정보 등 불필요한 메타데이터 제거
- 안전한 파일명 생성
- 경로 조작 방지
- 허용된 여행자 ID만 수정 가능
- 원자적 파일 쓰기 및 동시 저장 충돌 방지
- 손상된 메타데이터에 대한 복구 또는 백업 전략
프로필 이미지는 브라우저 저장소에 Base64 문자열로만 보관하지 않는다.
서비스 워커 등을 적용하는 경우 비공개 프로필, 인증 응답, 업로드 API를 무분별하게 캐시하지 않는다.
11. Render 배포
Render에서 실제 동작하는 배포 구성을 작성한다.
필수 사항:
- 프로덕션 빌드 및 시작 명령
- 환경변수 예시 파일
- Render가 제공하는 포트 사용
- 헬스체크 엔드포인트
- 영속 저장 경로 설정
- 배포 설명서
- 가능한 경우 유효한 render.yaml
- 서버 재시작 후 프로필 보존 확인 절차
Render의 최신 배포·디스크 정책은 공식 문서에서 확인한다.
서버 로컬 파일 저장이 자동으로 영구 보존된다고 가정하지 않는다. 업로드 파일과 프로필 JSON은 지원되는 영속 디스크에 저장한다.
선택한 요금제에서 영속 디스크를 사용할 수 없다면 그 제한을 명확히 설명하고, 데이터 보존 요구사항을 만족하는 구성을 제시한다. 무료 플랜에서 파일이 영구 보존되는 것처럼 안내하지 않는다.
파일 기반 저장은 단일 인스턴스 운영을 전제로 하고, 다중 인스턴스 확장이 필요한 경우의 제약을 문서화한다.
실제 배포 자격증명이 없으면 배포 완료라고 주장하지 말고, 배포 가능한 프로젝트와 정확한 설정 절차를 제공한다.
12. 공유 미리보기와 파비콘
페이지 완성 후 실제 디자인을 반영한 공유 썸네일을 제작한다.
- 제목: 마카오 가족여행
- 부제: 2026.10.12–10.15
- 권장 크기: 1200×630
- 작은 미리보기에서도 읽히는 글자
- 실제 사이트의 색상과 그래픽 사용

Open Graph와 관련 소셜 메타태그를 설정하고, 절대 URL과 이미지 접근 가능 여부를 확인한다.

공유 미리보기용 공개 메타데이터와 가족 전용 화면의 접근 보호가 함께 동작하도록 구성한다.
